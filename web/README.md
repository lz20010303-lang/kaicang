# 开仓控制器

本地运行的币安 U 本位合约开仓控制器。风控规则写死在程序里：以损定仓，风险金额等于账户余额的 5%，数量由止损距离自动计算并向下取整。用户的交易操作仍是三件事：填止损、选方向、开单。不能手填数量，不能改杠杆或保证金模式。程序不会自动选择方向。可按当前周期用均线或 Supertrend 辅助填写止损，但开仓仍以输入框里的数字止损和服务器闸门为准。页面上方的 MACD 金叉/死叉与小级别背驰只做参考，颜色随开单方向标绿或标红，绝不参与开单闸门。

界面是响应式网页，电脑和同一 Wi-Fi 下的手机浏览器都能打开。

## 硬规则

- 交易场所：币安 U 本位合约（USD-M 永续）
- 保证金模式：全仓（CROSSED），杠杆固定 20 倍，界面不可改
- 以损定仓：`风险金额 = 账户余额 × 5%`，`数量 = 风险金额 / |标记价格 − 止损价|`，再按合约 `stepSize` **向下取整**，绝不向上取整
- 入场按当前标记价格计算，开仓使用市价单
- 止损必填。做多止损必须低于标记价格，做空必须高于标记价格，距离必须大于 0
- 若取整后的数量不足最小下单量或最小名义金额，直接拒绝，不会为凑手数而放大仓位
- 开仓成交后立即挂 reduce-only 的 `STOP_MARKET`（按标记价格触发）。若止损单失败：测试网/实盘会尝试市价平掉刚开的仓；模拟模式会把该笔记为失败/未受保护，不会假装已经挂上止损，也不会留给观察任务去“悄悄平掉”
- **只能对自选中的交易对开单**。引擎和接口都会拦截，不只是前端限制。默认自选包含 `BTCUSDT`，不会预填一长串山寨币
- 数量由程序计算，用户和调用方即使传入数量也会被忽略

## 自选交易对

交易对选择器**只扫描自选列表**，不会列出币安全部合约。看上某个山寨币时，必须先加入自选，才能开单。

1. 在「自选交易对」区域输入币安 U 本位永续代码，例如 `1000PEPEUSDT`
2. 点击「加入自选」。程序会用币安公开 `exchangeInfo` 校验：只接受 USDT 计价、状态为 TRADING 的永续合约；未知代码或交割/非永续合约会被拒绝
3. 加入成功后，在自选列表里点选该交易对，当前交易对、标记价格、过滤器和开仓预览会切换过去
4. 可以从自选中移除。若该交易对仍有持仓，持仓和已有保护会继续显示，不会被悄悄拆掉；但移除后不能再对新仓开单

自选保存在 `data/watchlist.json`。不在自选中开单时，接口会返回：`该交易对不在自选中，请先加入自选后再开单`。

自选的增删与「填止损、选方向、开单」在界面上是分开的。杠杆、仓位和风险数字不能改。

## 周期与指标辅助填止损

交易操作区可以选 K 线周期：15min、1h、4h、1日，对应币安 U 本位 K 线周期 `15m`、`1h`、`4h`、`1d`。周期只是交易上下文，不会改杠杆、风险比例或仓位公式。

止损价旁有两个选择：**均线**和 **Supertrend**（超级趋势）。选中后，程序会用官方 U 本位 K 线接口 `GET https://fapi.binance.com/fapi/v1/klines` 拉取当前自选交易对、当前周期的 K 线，然后在本地计算指标。币安没有官方的「获取均线 / Supertrend」接口，指标值全部由本程序计算。

默认参数（界面上只显示简短标签，只能在配置或环境变量里改，不会作为交易操作旋钮）：

- 均线：收盘价 SMA 20（`MA_PERIOD`，默认 20）
- Supertrend：标准算法（HL2 / Wilder ATR），ATR 周期 10、乘数 3（`SUPERTREND_ATR_PERIOD`、`SUPERTREND_MULTIPLIER`）

只使用**最后一根已收盘**的 K 线计算指标值，不会用正在形成的未收盘 K 线。K 线会短暂缓存；切换交易对、周期，或再次点选均线 / Supertrend，以及改变方向时，会重新计算。

自动填写规则（确定性，不会猜）：

- 做多：仅当指标值严格低于当前标记价格时，才填入止损（价格下方的线）
- 做空：仅当指标值严格高于当前标记价格时，才填入止损（价格上方的线）
- 尚未选择方向：仍会计算；若指标在价格下方，先填入该值。之后若改选做空，会按空头规则重新评估；若此时指标不在价格上方，则清空止损并说明原因
- 指标在错误的一侧时（例如做多时均线在价格上方）**不会**填入无效止损，并给出中文说明，例如「当前周期均线在价格上方，不能作为多头止损」
- 填入的止损会按 tickSize 向「不收紧风险」的方向靠齐（做多向下、做空向上）
- K 线缺失、已收盘根数不足、拉取失败或指标值非有限数时，不猜测，止损保持为空并显示错误

这只是辅助填写。手动改止损价即视为切回手动输入。开仓和预览路径仍然只接受数字止损，并走原来的硬闸门（止损必填、方向正确、止损必须在正确一侧等），前端不能跳过服务端检查。可用 `GET /api/indicator` 在服务端用实时 K 线计算 `{interval, source, value, usable_for_side, reason}`，界面不以本地计算为唯一依据。


## MACD 金叉/死叉与小级别背驰（仅供参考）

交易操作区上方会标注当前周期的 MACD 交叉，以及下一级周期的 MACD 背驰。这两个标注**只做参考，不影响开单**：引擎和 `/api/open`、`/api/preview` 完全不读取 MACD 结果，风控门禁不变。网络失败时标注显示「获取失败」（灰色），不影响余额、预览、开单或其他功能。

数据来源仍是官方 U 本位 K 线 `GET https://fapi.binance.com/fapi/v1/klines`，在本地用收盘价计算标准 MACD（EMA）。只用已收盘 K 线，不用正在形成的那一根。默认参数：`MACD_FAST=12`、`MACD_SLOW=26`、`MACD_SIGNAL=9`（界面标签为 `MACD(12,26,9)`，只能在配置或环境变量里改）。

- **DIF** = EMA(收盘价, 12) − EMA(收盘价, 26)
- **DEA** = EMA(DIF, 9)；EMA 均以第一段窗口的 SMA 为种子
- **柱（histogram）** = DIF − DEA

### 当前周期：金叉 / 死叉

在当前所选周期（15min / 1h / 4h / 1日）的已收盘 MACD 上，取 DIF 与 DEA **最近一次交叉**：

- 金叉：上一根已收盘 K 线 DIF ≤ DEA，当前已收盘 K 线 DIF > DEA（DIF 上穿 DEA），偏向看多
- 死叉：上一根 DIF ≥ DEA，当前 DIF < DEA（DIF 下穿 DEA），偏向看空
- 同时给出距今几根已收盘 K 线（0 表示刚收盘那根就是交叉）、当前 DIF 在 DEA 上方还是下方、DIF 在零轴上方还是下方
- 可见历史里没有交叉则为「无交叉」

### 小级别：顶背驰 / 底背驰

小级别是当前周期的下一级：`1d→4h`，`4h→1h`，`1h→15m`，`15m→5m`。在小级别最近约 100 根（`MACD_DIVERGENCE_LOOKBACK`，默认 100）已收盘且已算出 MACD 的 K 线里，用 MACD 柱的符号分段找波段：

- 红柱段：连续 histogram > 0；绿柱段：连续 histogram < 0；histogram = 0 会断开分段
- 只比较**最后一段**（允许尚未反号、仍在延续）与窗口内**前一段同向柱**，更早的段不参与判定
- **顶背驰**（看空）：最后一段为红柱，该段价格高点（K 线 high）严格高于前一段红柱高点，但该段 **DIF 最大值**严格低于前一段 DIF 最大值
- **底背驰**（看多）：最后一段为绿柱，该段价格低点（K 线 low）严格低于前一段绿柱低点，但该段 **DIF 最小值**严格高于前一段 DIF 最小值
- 比较指标固定用「该段 DIF 极值」，**不用柱面积**。任一条件不是严格不等式，或窗口内不足两段同向柱，则为「无背驰」

### 颜色

金叉、底背驰偏向看多；死叉、顶背驰偏向看空。与当前选择的开单方向相同标绿，相反标红；未选方向或没有信号（无交叉 / 无背驰 / 获取失败）显示灰色。切换方向、周期或交易对时会实时刷新。

可用 `GET /api/macd?symbol=&interval=` 读取同一套结果。该接口是只读参考，不会下单，也不会改止损。

## 持仓与止损状态

页面和 `/api/state`、`/api/positions` 会显示当前持仓：交易对、方向、数量、开仓价、标记价、未实现盈亏、止损价，以及是否有挂着的 reduce-only 保护性止损。

若仓位未受保护，会有醒目告警，不会把它显示成已保护。模拟模式从本地台账读取；测试网/实盘从交易所持仓和当前挂单读取，不会虚构成交。

## 模拟止损触发与记账

仅在 `MODE=mock` 时，后台观察任务会轮询持仓的标记价格。当标记价格穿越止损（做多：`标记价 <= 止损价`；做空：`标记价 >= 止损价`）时，程序会平掉该模拟仓位、按盈亏更新模拟权益，并写入台账和操作日志。

**记账假设（仅模拟）**：以标记价格穿越作为触发条件，成交价按当时的标记价格记入台账。这是模拟簿记规则，**不是**实盘成交保证，也不保证按止损价完全成交。

测试网和实盘不会由本程序生成成交；只展示交易所的持仓与止损状态，触发和成交以交易所为准。

若开仓后止损挂单失败，仍走原来的失败路径（尝试市价平仓 / 标记为未受保护）。未受保护的模拟仓位不会被观察任务假装成“止损已成交”而悄悄平掉。

## 操作日志

每次预览、拒绝（含原因）、开仓、已挂止损、止损失败、止损触发平仓、失败路径平仓、自选增减，都会追加到 `data/ops.jsonl`（本地活动，已被 gitignore）。页面「操作日志」按时间倒序显示，时间使用 Asia/Shanghai。程序不会把 API Key 或其他密钥写入日志。

## 安装与运行

需要 Python 3.10+（开发时在 3.13 验证）。

```bash
cd /workspace/binance-open-controller
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

默认是模拟模式，**不需要 API Key**，直接启动：

```bash
python -m app.main
```

或：

```bash
uvicorn app.main:app --host 0.0.0.0 --port 8787
```

浏览器打开：`http://127.0.0.1:8787`

运行测试：

```bash
python -m pytest
```

可把 `.env.example` 复制为 `.env` 再按需修改。不要把填好密钥的 `.env` 提交到仓库。

## 模拟 / 测试网 / 实盘

由环境变量 `MODE` 选择，默认 `mock`。

| 模式 | 说明 |
| --- | --- |
| `mock` | 默认。无需密钥。可用公开接口拉取标记价格；网络失败时回退到该交易对最近一次成功价格或本地回退值。模拟开仓写入本地台账 `data/mock_ledger.json`，并更新模拟余额与持仓，后续风控按更新后的权益计算。被拒绝的申请不会写入台账。后台会按上面的记账假设检查止损是否触发。 |
| `testnet` | 币安期货测试网。需要 `BINANCE_API_KEY` 与 `BINANCE_API_SECRET`。不虚构成交。 |
| `live` | 币安期货实盘。除密钥外，必须同时设置 `ALLOW_LIVE=yes`，否则程序拒绝启动。绝不会默认进入实盘。不虚构成交。 |

测试网与实盘会读取合约账户的 `totalMarginBalance`（保证金余额/权益）；若该字段不存在则退回 `totalWalletBalance`。界面和本说明都会标出实际使用的字段名。下单前会把杠杆设为 20、保证金模式设为全仓；若已经是全仓，则忽略“无需更改”这类返回。

只有通过本程序的「开单」接口，才会调用交易下单接口。

- `ALLOW_LIVE=yes`（实盘额外开关）
- `MA_PERIOD=20`、`SUPERTREND_ATR_PERIOD=10`、`SUPERTREND_MULTIPLIER=3`（指标参数，仅配置可改）
- `MACD_FAST=12`、`MACD_SLOW=26`、`MACD_SIGNAL=9`、`MACD_DIVERGENCE_LOOKBACK=100`（MACD 参考标注参数，仅配置可改，不影响开单）

密钥只从环境变量或 `.env` 读取，程序不会把密钥写进日志或仓库。

## 公网链接与多人使用

任何人都能打开同一个链接，但**每个人只用自己的 API**，互不影响。

### 每人独立

- 浏览器第一次打开时生成一个随机 `client_id`（存在该浏览器的 localStorage），每次请求带请求头 `X-Client-Id`。
- 自选列表、操作日志、模拟账本都按 `client_id` 分开存放在 `data/clients/<client_id>/`。新用户的模拟账户从 `MOCK_BALANCE`（默认 1000 USDT）开始。
- 换浏览器或清除浏览器数据，就等于换了一个新身份（旧的模拟账户和自选看不到了）。
- 不带 `X-Client-Id` 的请求使用本机原来那一份状态（`data/mock_ledger.json` 等），方便本地脚本和测试。

### 页面底部「API 设置」

- 环境：模拟 mock（不需要 API）/ 测试网 testnet / 实盘 live。不填 API 就是模拟模式。
- API Key、API Secret **只保存在你自己的浏览器里（localStorage）**，可一键「清除」。
- 需要签名时，浏览器经 HTTPS 把 Key/Secret 放在请求头 `X-Bn-Key` / `X-Bn-Secret` 里发给本服务器，服务器只在这一次请求的内存里用它签名并转发给币安：**不写磁盘、不写日志、不进操作日志、不回传 Secret**。状态只显示 Key 前 4 后 4 位。
- 「保存并验证」会先用签名只读接口 `GET /fapi/v2/balance` 验证，通过后才保存并切换；失败时显示币安错误码和中文说明（如 `-2015` IP 白名单/权限/环境不符，`-1022` Secret 不对，`451` 地区限制）。
- 测试网和实盘模式下，余额和持仓直接读你自己的币安账户；保护性止损是交易所上的 `STOP_MARKET`，服务器不需要保存你的 Key。
- 实盘仍然需要**运行服务的人**在服务端设置 `ALLOW_LIVE=yes` 并重启。网页上无法打开实盘；没开时选择实盘会被服务器 403 拒绝。

> 诚实提醒：虽然服务器不保存 Key，但运行服务的那台电脑在处理请求的瞬间能看到它。只把 Key 填到你信任的人运行的服务上。

### 币安 API 建议

- 只勾「允许合约」，**不要开提现**。
- IP 白名单填服务器出口 IP（页面上会显示，来自 `https://api.ipify.org`）。所有用户共用这个出口 IP。
- 测试网 Key 需要在 testnet.binancefuture.com 单独申请，和实盘不通用。

### 风控对每个人都写死在服务端

20x、全仓、以损定仓 5%、止损必填、自选门禁都在服务端强制，前端改不了；每次开单前服务器用最新标记价格重新过闸。

### 防滥用

- 每个 IP 每分钟最多 `RATE_LIMIT_PER_MINUTE`（默认 240）次 API 请求，其中开单/改自选/验证 API 最多 `RATE_LIMIT_WRITE_PER_MINUTE`（默认 30）次。超出返回 429。经隧道访问时按 Cloudflare 传来的真实 IP 计数。
- `client_id` 只允许 16–64 位字母、数字、`-`、`_`，并校验路径，防止路径穿越。
- 最多 `MAX_CLIENTS`（默认 2000）个客户端目录；每人自选最多 50 个；模拟账户最多同时 20 个仓位，已平仓历史只保留最近 200 条；操作日志超过 256KB 自动只保留最近 500 条。
- 访问口令 `APP_TOKEN` 仍是可选项，默认不开（任何人都能打开页面）。

### 生成公网链接（免费、无需账号）

```bash
bash scripts/public.sh        # 重启服务（MODE=mock）+ Cloudflare Quick Tunnel，打印 https://xxx.trycloudflare.com
bash scripts/public.sh stop   # 停止
```

- 用的是 Cloudflare Quick Tunnel（`cloudflared tunnel --url http://127.0.0.1:8787`），不需要注册、不收费。脚本会自动下载 `cloudflared`（Linux / macOS）。Windows 可以手动下载 `cloudflared.exe` 后运行同样的命令。
- 链接写在 `data/run/public_url.txt`，日志在 `data/run/server.log`、`data/run/tunnel.log`。
- 临时链接每次重启隧道都会变；运行服务的电脑关机、断网或停掉脚本，链接就打不开。
- 隧道需要出站 7844 端口（UDP 或 TCP）。如果网络封了这个端口，链接会显示 Cloudflare Error 1033，脚本会提示。
- 服务器出口 IP 所在地区如果被币安限制，签名请求会返回 451；中国大陆网络通常直连不了币安接口。

## 部署到免费云平台（Render，Frankfurt）

仓库里已经带好 `Dockerfile`、`render.yaml`、`.dockerignore`，按 Render Blueprint 部署一个**免费** Docker Web Service，地区 **Frankfurt**。

为什么选 Frankfurt：币安对美国 IP 直接返回 HTTP 451（受限地区），也有人报告从新加坡云服务器调用 fapi 返回 451。Frankfurt 不在币安公布的禁止国家名单里，但能不能用最终以部署后页面顶部的自检为准。

部署步骤（需要你本人操作的只有注册/登录和授权）：
1. 把本项目推到你自己的 GitHub 仓库（可以是私有仓库）。
2. 注册/登录 https://render.com （可用 GitHub 登录）。Render 有时会要求绑卡做 1 美元预授权验证（会退回），这一步只能你本人完成。
3. Render 控制台 → New → Blueprint → 选这个仓库 → Apply。`render.yaml` 已指定 `plan: free`、`region: frankfurt`、`MODE=mock`、`ALLOW_LIVE=no`。
4. 部署完成后打开 `https://<服务名>.onrender.com`，看页面顶部：没有红字就说明本服务器能访问币安合约接口。

默认环境变量：`MODE=mock`、`ALLOW_LIVE=no`、`EPHEMERAL_STORAGE=yes`、`TRUST_PROXY=yes`、`REGION_PROBE=yes`。仓库和镜像里没有任何 Key。

### 启动自检（页面顶部红字）
服务启动后（之后每 30 分钟）调用两次币安主网合约接口，都**不带任何 Key**：
- 公开接口 `GET /fapi/v1/time`
- 签名接口 `GET /fapi/v2/balance`（不带 Key、假签名）。地区可用时币安返回 400/401（如 `-2014 API-key format invalid`）；地区受限时返回 **451**，被防火墙拦截时返回 **403**。

出现 451/403 时页面顶部显示红字提示。结果也可在 `/api/region-check` 查看。`/healthz` 给平台做健康检查，不访问外网。

### 免费平台的临时磁盘
Render 免费实例的磁盘是临时的：**重启、重新部署、空闲 15 分钟休眠后**，服务器上的 `data/`（每个浏览器的模拟账本、自选列表、操作日志）都会清空，页面上会用黄字提示。API Key 只存在各自浏览器里，不受影响；测试网/实盘的持仓和止损单在币安那边，也不受影响。空闲休眠后第一次打开大约要等 1 分钟。

### 出口 IP
Render 同一地区的所有服务共用一组出口 IP 段（不是固定单个 IP，固定 IP 要付费）。页面上显示的出口 IP 只是当前这一个，可能会变，所以在币安给 Key 设 IP 白名单可能会失效。不设白名单时，请务必只勾「允许合约」、关闭提现。

## API Key 使用建议

- 只开合约交易权限，**关闭提现**
- 为 Key 设置 IP 白名单
- 本机自用可放在 `.env` 或环境变量；公网多人使用时请在页面「API 设置」里填，Key 只存在各自浏览器
- 建议先用 `MODE=mock` 把流程跑通，再用测试网验证，最后才考虑实盘
- 实盘必须显式设置 `ALLOW_LIVE=yes`

## 接口概要

- 所有接口可带请求头：`X-Client-Id`（每个浏览器的随机标识）、`X-Bn-Mode`（mock/testnet/live）、`X-Bn-Key` / `X-Bn-Secret`（仅测试网/实盘，服务器不保存）
- `GET /api/server-info`：服务器出口 IP、是否开启实盘、Key 处理方式说明
- `POST /api/account/verify`：用请求头里的 Key 做签名只读验证（`GET /fapi/v2/balance`），返回成功或币安错误码的中文说明，不下单
- `GET /api/meta`：是否需要令牌、默认交易对、自选、模式
- `GET /api/state?stop=&side=&symbol=`：余额、标记价格、当前交易对、自选、持仓与止损状态、最近操作日志、指标默认参数；若带了止损和方向，同时返回预览（不在自选中会预览拒绝）
- `GET /api/indicator?source=ma|supertrend&interval=15m|1h|4h|1d&side=&symbol=`：用官方 K 线在服务端计算指标，返回 `{interval, source, value, usable_for_side, reason}` 以及可填入的止损（若不可用则 `fill` 为空）。这不是开仓接口，也不会下单
- `GET /api/macd?symbol=&interval=15m|1h|4h|1d`：只读参考。用官方 K 线在服务端计算 MACD(12,26,9)，返回当前周期金叉/死叉与下一级小级别顶/底背驰（`cross`、`divergence` 及中文 `label_zh`）。网络失败时仍返回 200 并标明「获取失败」。不参与开单或预览闸门，也不会下单
- `GET /api/positions`：当前持仓与是否存在未受保护仓位
- `GET /api/logs?limit=`：操作日志，最新在前
- `GET /api/watchlist`、`POST /api/watchlist` `{"symbol":"..."}`、`DELETE /api/watchlist/{symbol}`：查看、加入、移出自选
- `POST /api/preview`：`{"side":"LONG"|"SHORT","stop":"...","symbol":"..."}`，预览风险金额与计算数量
- `POST /api/open`：同样的请求体。服务端会在发送时重新取标记价格并重新过闸（含自选闸门）；若价格已变动导致止损无效或数量不达标，或交易对不在自选中，直接拒绝

## 已知限制

- 以损定仓按止损价本身计算，**不含手续费和滑点**。实际成交价、资金费和双边 taker 费可能让亏损大于账户余额的 5%。
- 保护性止损按标记价格触发（`workingType=MARK_PRICE`）。极端行情下仍可能出现滑点，`STOP_MARKET` 不保证完全按止损价成交。
- 模拟止损以“标记价格穿越即按当时标记价记账”为假设，与实盘撮合、排队和滑点不同；测试网/实盘不使用这套虚构成交。
- 模拟模式的标记价格依赖币安公开接口；网络不可用时使用该交易对最近一次成功价格，若从未成功则回退到 `100000`，与真实盘口可能不一致。
- 模拟模式会按 20x 全仓占用保证金；保证金不足时由模拟交易所拒绝（这是交易所约束，不是额外风控规则）。模拟权益会随持仓浮动盈亏变化，但不会模拟部分成交、强平等复杂场景。
- 交易对过滤器（`tickSize`、`stepSize`、`minQty`、最小名义金额）在能访问公开/交易所接口时使用实时值，失败时回退到 BTCUSDT 的常用默认值。实际规则以交易所为准。
- 止损会按 tickSize 向“不收紧风险”的方向靠齐（做多向下、做空向上），再按靠齐后的止损计算数量。
- 加入自选需要能访问币安公开 `exchangeInfo`。网络失败时不会把未校验的代码加入自选。
- 本程序不是全功能交易终端：没有止盈、没有自动移止损，也不会根据行情自动选择方向。均线 / Supertrend 只按规则辅助填止损；MACD 标注只做参考。开仓仍以数字止损和服务器闸门为准。
- 均线和 Supertrend 都是滞后指标，反映的是已收盘 K 线，不是未来走势，也不能保证止损距离合适。
- 指标使用最后一根已收盘 K 线，当前尚未收盘的那根不会参与计算，因此刚开盘后可能仍显示上一根已收盘的值，会有周期延迟。
- 拉取官方 K 线依赖网络。网络失败、K 线不足或返回无效数据时，不会猜测指标值，也不会自动填止损。
- 模拟 / 测试网模式下的标记价格若与官方实盘 K 线来源不一致，指标相对标记价格的上下关系可能和你在交易所软件里看到的略有差别；计算本身仍只用官方 USD-M K 线。
- 页面上方的 MACD 金叉/死叉与小级别背驰只是用已收盘 K 线算出的参考标注，不是交易信号，也不保证随后的价格方向。判定规则是写死的（最近一次交叉、最近两段同向柱的 DIF 极值比较），与部分行情软件或缠论里对「背驰」的习惯画法可能不一致。
- MACD 与背驰同样只使用已收盘 K 线，未收盘的当前 K 线不参与计算；网络失败时只把标注改成「获取失败」，不会改止损，也不会阻止开单。
- 若开仓已成交而止损失败、随后平仓也失败，程序会明确报错并告警未受保护，但无法在网络或权限异常时保证一定能平掉，需要立即人工检查交易所账户。
- 公网多人使用时，所有人的签名请求都从同一个服务器出口 IP 发往币安，共用币安按 IP 计算的请求权重；人多时可能被限速（-1003 / 429）。页面在测试网/实盘模式下降到每 8 秒刷新一次以减轻压力。
- 模拟账户按浏览器区分，没有登录体系；清除浏览器数据就会换成新的模拟账户。
